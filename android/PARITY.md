# 与 iOS 的功能对照

基础对照为 iOS 0.1.0 Build 17（`6cdfb5d`，`mb-ios-v0.1.0` 标签）。安卓 0.1.1 预览版部分跟进 Build 18（`65078a7`）的布局与系统歌词，系统 OAuth 尚未移植。此表区分已实现、已实测和待验收；APK 可构建不等于已经齐平。

0.1.1 重新设计发现页推荐封面、曲目列表、手机底栏、迷你播放器和全屏播放页。发现页音源放在工具栏下方独立横滑的一行。

## 验证方式

- 0.1.1 使用 JDK 17 与锁定 Gradle Wrapper。执行 `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest`，102 项 JVM 测试、Android 16 无窗口 AVD 上 30 项设备测试通过。Lint 0 错误、29 警告。Debug APK 签名和 16 KB APK 对齐检查通过，包内含四种 ABI 的 QuickJS 库。覆盖升级至 0.1.1 后原歌单文件仍在；播放上报和退出电台测试使用专用安装与初始空队列。
- 0.1.1 界面改版在浅色手机模式实测游客 B 站发现、开始播放、迷你播放器与全屏播放页。截图：`android-design-discover-light.png`、`android-design-mini-light.png`、`android-design-player-light.png`。以下其余截图记录的是对应功能的既往回归，不代表新版各屏幕尺寸都已复测。
- Android 15 和 Android 16 ARM64 独立临时 AVD 以 `-no-window -no-audio -no-snapshot` 启动，ADB 定向所用设备。游客流量不携带账号 Cookie，演示本地音频为生成的测试音，不包含用户文件。
- Android 16 无窗口刷新回归：真实游客 B 站首页和音乐榜断网下拉后保留旧曲目并显示重试，联网后可再刷新；音乐榜“播放全部”将当时的 20 首曲目入队。QuickJS 测试插件的首页及自定义页实测刷新失败保留旧内容，下一次下拉成功替换为新内容。截图：`android-plugin-refresh-offline.png`。
- Android 16 无窗口备份回归：外部备份的音频和插件 ZIP 各改一个字节但保持长度。“立即备份”用本机原件逐字节修复两份文件，未重写有效插件包或改动旁边的非备份文件。卸载后索引原样保留，重装重选原目录恢复逐字节相同的音频、歌单和暂停队列，恢复的插件保持停用。
- Android 16 无窗口下载资料库回归：原音源停用时从资料库播放测试 WAV，播放页点本地喜欢。备份后卸载重装、重新授权原文档目录，核对音频 SHA-256 及喜欢/播放时间戳一致，“喜欢”和“最近播放”均出现下载曲目。截图：`android-download-liked-player.png`、`android-download-liked-restored.png`、`android-download-recent-restored.png`。
- Android 16 无窗口专辑回归：递归导入两层目录下的三首带标签测试 M4A，同名专辑分成两组，合辑按曲号排序。专辑与歌单多词过滤后，“播放全部”只入队匹配歌曲；随机播放从选中曲开始。手动备份、卸载重装并重选原文档目录，三首曲目的目录摘要原样恢复，专辑仍分两组。截图：`android-local-album-detail.png`、`android-local-albums-restored.png`。
- Android 16 无窗口歌词与备份回归：从校验通过的独立目录补回旧版本留下的截断音频；重新备份并卸载，确认外部索引原样保留。重装重选目录后，三首歌词逐字一致，恢复的八个插件均停用；系统回收缓存后，七首导入曲目和两首下载歌曲的 SHA-256 不变。恢复的 LRC 正常显示并高亮，截图：`android-local-lyrics-restored.png`。
- 选择内有同名 `MB Data` 文件的目录时，中文和英文均显示冲突提示，原备份绑定与同名文件内容保持完整。截图见 `android-backup-conflict-zh.png` 和 `android-backup-conflict-en.png`。
