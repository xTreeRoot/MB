# 播放器、下一首预加载与账号兼容

2026-11-19，产品版本 0.1.0（20），宿主兼容版本 0.1.26。

播放器全屏展示，取消底部额外留白，保留 Home 指示条安全区和“从封面展开”设置。随机/循环操作显示中文反馈，底部提供歌词、评论点赞、音频输出和待播清单的小字。横屏提供歌词、律动、待播清单、选歌和评论，评论区不重复展示曲目信息；选歌与队列直接控制当前播放会话，评论复用现有分页与点赞能力，律动沿用逐字时间，并遵循减少动态效果设置。

音乐和视频使用统一的细进度条，圆点默认 9pt、拖动 12pt，触控区仍为 44pt。视频画面单击切换控制条，双击播放/暂停；播放中 4 秒无操作收起，暂停、拖动和继续操作会取消旧收起任务。普通页和全屏使用同一套手势。

播放到 70% 后，准备自动播放顺序中的下一首，只解析地址和预读首个 256 KiB 分段，不创建第二个播放器、不提前播放、不改变当前曲目。切歌复用同一 RemoteMediaAsset 的分段缓存；90 秒后不复用旧准备，载入失败重新解析。修改队列、随机/循环、音质、切源、暂停、拖回阈值之前或视频接管均取消预备任务。预取失败保持静默。

YouTube Music 0.1.6 将 OAuth 账号验证改为官方 YouTube Data API `channels.list(part=snippet,mine=true)`，避开实际返回 HTTP 400 的网页 `account/account_menu`。官方合同对照 googleapis/google-api-go-client 的 youtube/v3/youtube-api.json；无频道和 API 失败明确报错，不保存未验证会话。用户已确认新版 YouTube 授权登录成功；个人音乐库继续使用上游接口，尚未独立验收。

汽水音乐从 0.2.2 更新到 0.3.2。已加入账号、个人歌单及扫码切换 App 后的有限断线恢复；真机诊断发现 -1005，恢复后用户仍反馈平台业务拒绝。因此汽水账号问题尚未修复完成。0.3.2 增加拒绝阶段和数字错误码，尚未在手机复现后验证；不把自动化合同通过视为真实登录成功。Node 18 项、QuickJS 合成账号与私密歌单、断线恢复回归通过。

MB Service 节点的 `/healthz` 正常，`/v1/sessions/bilibili` 返回预期未认证，`/v1/data/bilibili/profile` 返回普通 404；server 分支没有实现 `/v1/data`。因此“节点不支持此同步功能”来自服务端缺少资料同步接口，非密码错误。本轮未修改或部署服务端。

## 验证记录

Swift 全量 173 项通过，包含预加载阈值、取消与迟到结果、切歌缓存复用、过期回退、视频控制状态、旧代理策略迁移和两插件 QuickJS 合同。YouTube Node 15 项、汽水 Node 18 项与语法检查通过。

旧后台计时器测试用固定 80ms 后读取，重负载时可能先读取后触发；改为等待真实首个定时事件后验证，消除对机器调度速度的依赖。

iPhone 在 build 19 的最终回归中，播放器中文反馈、横屏五分区和评论可见性、视频单击收放与双击互斥两项通过（Player19PhoneAccepted.xcresult）。iPad build 19 初版两项通过，但随后版本的播放器方向回归未通过；视频手势回归通过。当前源码进一步调整了方向请求和 iPad 呈现，最新回归在用户要求立即推送时停止，不能视为最终界面验收通过。
